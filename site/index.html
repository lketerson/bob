AI Engineering Framework

Build on Base.

Uma especificação que o seu agente de IA lê para criar e manter o .ai/ — a fonte única de verdade de engenharia de IA do projeto. Agnóstica de stack e de provedor.

Começar Ver no GitHub

Por que existe

A evolução rápida da IA trouxe um crescimento desenfreado de documentação nos repositórios, sem um padrão comum: cada desenvolvedor acaba montando seu próprio setup, gerando resultados destoantes entre pessoas do mesmo time.

BoB resolve isso com uma única fonte de verdade por projeto, que qualquer agente e qualquer desenvolvedor segue da mesma forma. Ferramentas específicas (Claude, Copilot, Cursor, Codex…) recebem só um adaptador mínimo apontando de volta para .ai/, nunca uma cópia divergente.

Quickstart

Novo projeto

  1. Aponte seu agente de IA para o repositório do BoB e peça para seguir start.md.
  2. Rode o comando abaixo.
  3. Responda o bootstrap interativo (idioma, ferramentas de IA, board, agentes, skills, MCPs) e aprove o preview antes da gravação.
  4. .ai/ nasce estruturado para o projeto.

Codebase existente

  1. Mesmo ponto de partida: start.md e /bob-start.
  2. O BoB descobre stack, docs e convenções antes de perguntar qualquer coisa.
  3. Se já existir um .ai/ de outra origem, ele pergunta se você quer migrar — nunca reorganiza em silêncio.
  4. Rode /bob-map-codebase para mapear o contexto com evidência real.

FAQ

Por que "BoB"?

Build on Base — o nome do framework e do diretório canônico (.ai/) que ele cria em cada projeto.

Por que a spec é dividida em vários arquivos?

Um arquivo único obrigaria a carregar conteúdo irrelevante para a tarefa atual. spec/ segue divulgação progressiva: leia só o que a tarefa precisa.

Qual a diferença entre spec/ e templates/?

spec/ define o que cada peça do .ai/ deve conter e quais regras seguir. templates/ é o conteúdo já pronto para copiar.
