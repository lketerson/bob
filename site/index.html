AI Engineering Framework

Build
on Base.

Uma especificação que o seu agente de IA lê para criar e manter o .ai/: a fonte única de verdade de engenharia de IA do projeto, independente de stack e de provedor.

Começar Ver no GitHub ↗

Por que existe

A IA mudou rápido e os repositórios encheram de documentação sem padrão. Cada desenvolvedor monta o próprio setup, e o time inteiro colhe resultados diferentes.

O BoB define uma fonte de verdade por projeto, que qualquer agente e qualquer pessoa segue do mesmo jeito. Claude, Copilot, Cursor e Codex recebem só um adaptador mínimo apontando de volta para .ai/, nunca uma cópia que diverge.

Quickstart

Dois pontos de partida, o mesmo comando.

$ /bob-start

Projeto novo

  1. Aponte seu agente para o repositório do BoB e peça para seguir start.md.
  2. Rode /bob-start.
  3. Responda o bootstrap: idioma, ferramentas de IA, board, agentes, skills, MCPs. Aprove o preview em start.temp.md.
  4. O .ai/ nasce estruturado para o projeto.

Codebase existente

  1. Mesmo ponto de partida: start.md e /bob-start.
  2. Antes de perguntar qualquer coisa, o BoB descobre stack, docs e convenções que já existem.
  3. Se já houver um .ai/ de outra origem, ele pergunta se você quer migrar. Nunca reorganiza em silêncio.
  4. Rode /bob-map-codebase para mapear o contexto com evidência real.

FAQ

Por que “BoB”?
Build on Base: o nome do framework e do diretório canônico (.ai/) que ele cria em cada projeto.
Por que a spec é dividida em vários arquivos?
Um arquivo único obrigaria a carregar conteúdo que a tarefa não usa. spec/ segue divulgação progressiva: leia só o que a tarefa pede.
Qual a diferença entre spec/ e templates/?
spec/ define o que cada peça do .ai/ deve conter e quais regras seguir. templates/ é o conteúdo pronto para copiar.
